- 지금 구현된 "AI 상대 실시간 레이스 + 판돈"은 **유저에게 보이는 모드가 아니다.** 랭크 매칭이 길어질 때 서버가 조용히 붙이는 대체 상대(봇)의 두뇌로 쓰고, 개발·테스트 진입점으로만 남긴다. 싱글 캠페인은 여기서 상대·판돈·미니맵을 뺀 것이고, 랭크·친구 대전은 상대를 네트워크 너머의 사람으로 바꾼 것이다. 친구 대전은 랭크 대전의 **매칭 큐만 초대 코드로 바꾼 것**이라 네트워크 코드가 같다.
- 로비(DESIGN 01) CTA: **[전투 시작]**(gold L, 싱글 캠페인) → **[⚔ 레이즈 듀얼]**(purple M) → 시트에서 **[랭크 대전] [친구 대전]** 중 선택. "AI 대전"이라는 이름은 어디에도 나오지 않는다(결정 1). 첫 실행은 캠페인 튜토리얼로 고정.

### 1.1.1 숨김 대체 매칭 (봇·고스트)

매칭이 오래 걸리면 유저에게 묻지 않고 **일반 상대처럼 보이는 대체 상대**를 붙인다.

| 단계 | 시각 | 동작 |
|---|---|---|
| 1 | 0~15초 | 실제 유저만 (레이팅 ±100 → 10초마다 +50) |
| 2 | 15~40초 사이 랜덤 시점 | 고스트(레이팅 근처 유저의 검증된 과거 판) 후보가 있으면 고스트를 붙인다 |
| 3 | 고스트도 없으면 같은 시점 | 봇(현재 `OpponentAI` + 베팅 성향) 을 붙인다 |

- 대기 종료 시각을 15~40초 사이에서 무작위로 골라 "항상 40초 뒤에 잡힌다"는 패턴이 안 보이게 한다. 매칭 성사 연출(VS 충돌)은 실제 유저와 똑같다.
- 대체 상대는 **닉네임 풀**(수트 단어 조합, 예: "하트왕 민수", "심연의 궁수")·아바타·레이팅(플레이어 ±80)을 갖는다. 같은 유저에게 같은 닉이 연속으로 나오지 않게 최근 5판 닉을 피한다.
- 봇 행동은 사람처럼: 카드 생각 시간 1.5~4초(현재 구현), 베팅 응답 0.8~2초, 레이즈·블러핑 성향(`duel.json ai`), 이탈 없음. 봇 강도는 플레이어 레이팅 구간별 프리셋 3개(하위 = 무전략에 가깝게, 중위 = smart, 상위 = smart + 업그레이드 우선)로 **승률 45~55%**가 나오게 맞춘다 — `npm run sim`의 봇 저지선(8/13/18)이 강도 조절 손잡이.
- 랭크 반영: 플레이어 레이팅은 정상 반영하되 **K를 절반**(16)으로 — 봇 상대로 레이팅이 부풀거나 꺼지는 폭을 줄인다. 시즌 포인트는 동일. 봇 쪽 레이팅은 기록하지 않는다.
- 서버 기록: `matches.opponent_kind = human | ghost | bot` (내부 통계용, 클라이언트 UI에 노출 안 함). 대체 매칭 비율은 운영 지표로 본다(높으면 매칭 풀 부족 신호).
- 오프라인이면 같은 흐름으로 봇이 붙되 결과는 랭크에 반영하지 않는다(서버 검증 불가). 온라인 복귀 시 동기화할 것도 없다.
- 약관·스토어 설명에 "매칭 상대에 AI가 포함될 수 있습니다" 한 줄은 넣어 두길 권한다 — 화면에는 표시하지 않더라도 분쟁을 막는 최소 문구다.

### 1.1 싱글 캠페인 규칙

- 상대 없음. 상단 상대 바·미니맵·판돈 행이 사라지고 그 자리에 **다음 웨이브 예고**(공중/보스)와 **최고 기록 비교**("내 최고 R27")가 들어간다.
- 광고 3종(GDD §9.2) 전부 이 모드 전용. 패배 화면은 DESIGN 06(카운트다운 5초 + 부활 ♥3, 판당 1회).
- 메타 업그레이드(교환 +1·타이머·시작 골드)·카드 교환권·메타 영웅 해금 전부 적용.
- 진행 저장: 라운드 단위 자동 저장(`localStorage`) → 앱을 껐다 켜도 이어하기. 저장 시점은 카드 페이즈 시작.
- 일일 미션(§9.4): "스트레이트 조각 2개", "공중 웨이브 5회 무피해", "라운드 25 도달" 같은 캠페인 전용 과제 3개, 다이아 10.
- 난이도: 기본 곡선 유지(봇 기준 23/25/32). 클리어 후 **하드(+1 별)** 해금: hpGrowth 1.19, 보스 조각 1개. 별은 로비 트로피 알약에.

### 1.3 친구 대전 규칙 (③)

**진입 흐름**

```
로비 [레이즈 듀얼] → [친구 대전]
  ├─ [방 만들기] → 6자리 코드(예: K7Q2M4) + [초대 링크 공유] (OS 공유 시트: 카카오톡·문자 등)
  │     링크: https://pokerdefense.app/j/K7Q2M4  (앱 있으면 딥링크로 방 화면, 없으면 스토어)
  └─ [코드로 참가] → 코드 6자리 입력 (클립보드에 코드가 있으면 자동 채움)
방 화면(09 변형): 방장 아바타·닉 | VS | 친구 아바타·닉(입장 전엔 "초대 대기 중… 코드 K7Q2M4 [복사]")
  방장만 규칙 토글 → 양쪽 [준비] → 3초 카운트다운 → 듀얼 GameScene
```

**방장이 고르는 규칙** (기본값 = 랭크 대전과 동일, 바꾸면 방 화면에 "커스텀" 배지)

| 규칙 | 기본 | 선택지 | 비고 |
|---|---|---|---|
| 웨이브 | 20 | 20 / 40 | 40은 캠페인 곡선 그대로 (긴 판, 15~20분) |
| 교환권 | 매치당 3회 | 0 / 3 / 무제한 | 랭크는 3 고정 |
| 판돈 걸기 | 켬 | 켬 / 끔 | 끄면 순수 레이스. 초보 친구용 |
| 영웅 | 전부 개방 | 전부 / 각자 해금분 | "각자"는 메타 해금을 뽐내고 싶을 때 |
| 손패 | 각자 랜덤 | 각자 / **동일 손패** | 동일 손패 = 두 사람이 같은 5장·같은 덱 순서. 순수 판단력 대결. 이 옵션은 손패 시드를 공유하므로 교환 결과도 같은 덱에서 나온다 |
| 배속 | ×1 | ×1 / ×2 | 둘 다 같은 값이면 공정 |
| 메타 업그레이드 | 미적용 | 미적용 / 적용 | 적용은 "각자 해금" 영웅과 세트로만 |

- 방 코드는 10분 유효, 방장이 나가면 방 폐기. 입장 후 상대가 나가면 결과 없이 로비로(전적 미기록).
- 판 끝에 **[재대결]**: 한쪽이 누르면 상대에게 배지, 둘 다 누르면 새 시드로 즉시 다음 판(규칙 유지). 시드는 매 판 서버가 새로 발급.
- **친구 목록**: 코드로 한 번 붙은 상대는 "최근 대전"에 남고, [친구 추가]하면 친구 목록에서 바로 초대(온라인이면 푸시 알림 "OO님이 대전을 걸었어요"). 친구별 상대 전적(3승 2패)·최근 5판 결과.
- 랭크 미반영, 판돈 골드도 매치 안에서 소멸(§10.5). 보상은 일일 미션 "친구 대전 1판"(다이아 10)과 친구 전적뿐 — 부계정 어뷰징 여지 없음.
- 로그 검증은 랭크와 같은 파이프라인을 태우되 실패해도 매치 무효만(제재 없음). 친구끼리라 치팅 유인이 적다.
- 관전(친구 방 3인 이상)은 E단계 이후. 지금은 2인 방만.

### 1.4 왜 "동기 라운드"가 아니라 "레이스"인가

GDD §10.2는 30초 동기 라운드를 그렸지만, 현재 구현한 레이스(각자 진행, 라운드별 판돈 판정)가 온라인에 더 맞다.

- 네트워크가 끊겨도 내 판은 멈추지 않는다. 상대 상태는 "보이기만" 하면 된다.
- 락스텝이 없다. 각 클라이언트는 **자기 보드만** 결정론 시뮬로 돌리고, 상대 보드는 스냅샷으로 그린다.
- 판돈 판정은 이미 비동기 설계다(`Betting.sync`: 각자 라운드 진입 시 앤티, 양쪽 성적 보고 시 판정).
- 유일한 공정성 요구는 **벽시계**: 둘 다 같은 순간에 시작하고 배속이 같으면 된다. 서버가 시작 시각과 각 라운드 종료 타임스탬프를 검증한다.

## 2. 아키텍처

### 2.1 GameMode 설정 (코드 한 장)

```ts
interface GameMode {
  id: 'campaign' | 'ranked_duel' | 'friend_duel';   // 봇 상대는 모드가 아니라 opponent: 'ai'로만 구분 (UI 비노출)
  waves: 40 | 20;                 // duel-config.json 사용 여부
  opponent: 'none' | 'ai' | 'ghost' | 'live';
  betting: boolean;
  ads: boolean;                   // 교환+1·부활·골드2배 버튼 노출
  applyMeta: boolean;             // 메타 업그레이드·교환권
  allHeroes: boolean;             // 12종 전부 개방
  speedLock: boolean;             // 배속 버튼 숨김
  seed: 'random' | { match: string; wave: number; hand: number; sharedHand?: boolean }; // sharedHand = 친구 대전 "동일 손패"
  rewards: 'campaign' | 'practice' | 'ranked' | 'friendly';
  /** 친구 대전 방장 옵션. 랭크는 고정값이라 undefined */
  custom?: { waves: 20 | 40; betting: boolean; allHeroes: boolean; sharedHand: boolean; speed: 1 | 2; applyMeta: boolean };
}
```

- `FRIEND_DUEL` 프리셋 = `RANKED_DUEL` + `rewards: 'friendly'` + `custom` 병합. 방 화면의 토글이 `custom`을 만들고, 양쪽 클라가 같은 `GameMode`를 서버 방 레코드에서 받는다.

- `GameScene`은 `scene.start('Game', { mode })`로 받아 UI 조각을 켜고 끈다. 로직은 `GameLoop`/`Betting` 그대로.
- `OpponentSource` 인터페이스로 상대를 추상화한다. `AIOpponent`(현재 `OpponentAI`), `GhostOpponent`(기록 재생), `LiveOpponent`(네트워크 스냅샷) 세 구현. `OpponentMiniMap`·`OpponentPanel`·`BetBar`는 이 인터페이스만 본다.

```ts
interface OpponentSource {
  tick(dt: number): void;                 // AI/고스트는 진행, Live는 no-op
  readonly view: OpponentView;            // wave, life, gold, phase, units(슬롯·수트·티어), hero, enemies(좌표·hp), exchangeCount, lastHandRank
  readonly finished: boolean;
  readonly side: BetWallet;               // Betting이 앤티·판돈을 반영할 지갑 (Live는 서버 값 미러)
}
```

### 2.2 결정론과 입력 로그 (온라인의 뼈대)

이미 지켜지고 있는 것: 카드·전투·소환·시너지·영웅 스킬의 난수는 전부 주입 `rng`. 씬만 `Math.random`을 쓴다 → 온라인 모드는 서버 시드로 교체.

**입력 로그** = 한 판을 완전히 재현하는 최소 정보. 라운드마다:

```ts
interface RoundInput {
  wave: number;
  exchanges: number[];             // 교환한 카드 인덱스 순서 (교환권 포함)
  confirmedAt: number;             // 라운드 시작 후 초
  manage: { moves: [from, to][]; sells: number[]; merges: string[]; upgrades: Suit[]; hero?: string };
  combatStartAt: number;
  skills: number[];                // 스킬 사용 전투 시각(초)
  bet: { action: 'check' | 'raise' | 'call' | 'fold'; at: number }[];
  result: RoundReport;             // 잃은 하트·클리어 시간·족보 (자기 보고)
}
```

- 스킬은 전투 시각 기준으로 기록되고, 재생 시 같은 tick에 실행된다 → `tickCombat(dt)`의 dt를 고정(0.1s)으로 통일해야 재현이 맞는다. **온라인 모드는 시뮬 step을 0.1초 고정**, 렌더는 보간.
- **구현(B단계)**: 로그의 재생용 본문은 라운드별 순서 있는 `ops`(교환 x/xt, 확정 c, 이동 mv, 판매 sell, 합성 mg, 업그레이드 up, 영웅 hero, 전투 시작 go, 스킬 sk@step, 외부 골드·하트 g/l@step). 요약 필드(exchanges·manage·skills…)는 개연성 검사용으로 함께 남긴다. 난수는 라운드마다 다시 시드를 잡아(손패 = 시드+플레이어+라운드, 전투 = 시드+라운드) "동일 손패" 규칙에서 앞 라운드 교환 횟수가 달라도 다음 패가 같다. 판이 중간에 끝난 마지막 라운드는 `partial` + 진행 step 수로 남는다. 판돈으로 오간 g/l 값이 판돈 규칙과 맞는지는 양쪽 로그 교차 검증(E단계)에서 본다.
- 검증: 서버(또는 상대 클라이언트)가 시드 + 로그로 `GameLoop`을 헤드리스로 다시 돌려 `RoundReport`가 일치하는지 확인. 불일치 = 치팅 판정 → 매치 무효.
- 손패는 로그에 없어도 시드로 복원된다(시드 스트림이 결정). 그래서 **상대에게는 손패를 보내지 않는다**(§10.6). 쇼다운 공개는 라운드 판정 후 서버가 "이 라운드 손패" 5장만 전달.

### 2.3 네트워크 모델 — 릴레이 + 사후 검증

```
클라 A ──(이벤트/스냅샷)──▶ 서버(릴레이·매치 상태) ──▶ 클라 B
   │                                  │
   └──(라운드 로그)────────────────────┘  ← 검증(헤드리스 재생), 판정 확정, 랭크 반영
```

- **자기 보드는 자기 클라이언트가 권위**(즉시 반응, 지연 0). 서버는 릴레이와 사후 검증만.
- 상대에게 보내는 것(공개 정보, §10.6): 라운드 진입, 교환 장수, 족보 확정(등급만), 소환된 유닛·배치, 판매/합성/업그레이드 결과(필드 상태), 영웅 소환(공개 이벤트), 베팅 액션, 전투 스냅샷(2 Hz: 적 좌표·hp·유닛 슬롯), 라운드 성적.
- 보내지 않는 것: 손패, 아웃 수, 행운 게이지 레벨, 조각 보유(진행도는 공개해도 무방 — 심리전 재료로 공개 권장).
- 대역폭: 스냅샷 ≤ 30 적 × (pos 2B + hp 1B) + 25 슬롯 = 수백 바이트, 2 Hz → 무시할 수준.
- 판돈 판정은 양쪽 클라가 같은 `RoundReport` 쌍으로 같은 순수 함수를 돌리므로 결과가 같다. 서버가 검증 후 "확정" 이벤트를 보내면 UI가 그때 골드를 반영(그 전엔 "판정 대기" 표시).

### 2.4 서버 스택 (솔로 개발 기준)

| 단계 | 필요 기능 | 추천 | 이유 |
|---|---|---|---|
| **고스트전** | 로그 저장/조회, 프로필, 매칭 큐 | **Supabase** (Postgres + Auth + Edge Functions) | 서버 코드 거의 없음. 검증은 Edge Function(Deno)에서 `src/systems` 번들을 그대로 실행 |
| **친구 대전** | 방 코드·초대 링크·재대결·친구 목록 | Supabase `rooms` 테이블 + Realtime 채널(`room:<code>`) + 딥링크(Capacitor App 플러그인) + Web Share API | 매칭 큐가 없어 실시간 기능 중 **가장 먼저** 만들 수 있다. 지인 비공개 테스트(GDD Phase 5)의 도구가 된다 |
| **실시간 랭크** | 방·릴레이·존재(presence)·매칭 큐 | 친구 대전과 같은 채널 구조 + `queue` 테이블(매칭은 Edge Function cron 5초) | 릴레이만 하면 되므로 Realtime 채널로 충분. 권위 서버가 필요해지면 Colyseus로 이전 |
| **랭크·시즌** | 리더보드, 시즌 리셋, 보상 지급 | Supabase 테이블 + cron | |

- 클라 쪽은 `MatchTransport` 인터페이스 하나로 감싼다: `send(event)`, `on(event)`, `presence`. 고스트전은 Transport 없이 로그 파일을 읽는 `GhostOpponent`.
- `src/systems`는 Phaser 의존이 없어 Deno/Node에서 그대로 돌아간다 — 검증 함수 = `replayMatch(seed, log) → RoundReport[]` 하나.

### 2.5 데이터 모델

```

seasons       id, starts_at, ends_at, rewards(json)
```

### 2.6 랭크

- 레이팅 1000 시작, ELO-lite: 기대승률 `1/(1+10^((R_b-R_a)/400))`, K=32(플래시 배치 10판은 K=64).
- 매칭 범위: 처음 ±100, 10초마다 +50, 최대 ±400. 15~40초(랜덤) 넘으면 고스트 → 봇 순으로 자동 매칭(§1.1.1). 대기 화면(DESIGN 09)은 그대로 "매칭 중… 00:07" + TIP.
- 시즌 4주. 시즌 포인트는 승리 +20/패배 −8(바닥 0) — 레이팅과 별개로 "많이 하면 오르는" 지표. 시즌 보상: 다이아·카드 뒷면 스킨(§9.3 "런칭 후").
- 연승 3 이상은 앤티 감면 없음(컴백 장치는 하트 기준만) — 실력 외 변수 최소화.

## 6. 밸런스·심의·리스크

- **20웨이브 곡선**: 40웨이브의 W1~40을 W1~20으로 압축하면 성장 시간이 부족해 T1 몰빵이 유리해진다. 시작 골드 100 유지하되 클리어 골드를 `40 + wave×8`로 올려 업그레이드 속도를 맞춘다. 봇 저지선 목표 W11~13(캠페인 23의 절반), `tests/Balance.test.ts`에 모드별 목표 추가.
- **영웅 등급**: 20웨이브에선 S=남은 10+, A=5+, B 그 외 (`duel-config`). 조각 요구량 3 유지, 보스 조각은 5/10/15에서 1개(2개면 너무 이르다) — `npm run shards -- --mode duel`로 재측정.
- **심의**: 판돈은 매치 내 골드만, 스토어 문구 "레이즈/판돈 걸기", PvP 포함 시 12세→15세 재검토(§10.5). 랭크 보상에 현금성 재화 없음.
- **치팅**: 로그 검증 불일치·타임스탬프 역전·배속 위반은 매치 무효 + 3회 누적 시 랭크전 제한. 클라 권위이므로 "보이는 정보"만으로는 이득이 없게 설계(손패 비공개).
- **결정론 드리프트**: 시뮬은 순수 JS 수치 연산이라 기기 간 동일. 위험 요소는 (1) `Math.random` 잔재 (2) 가변 dt. 둘 다 B단계 테스트로 잠근다.
- **이탈/지연**: 레이스 룰이라 상대 지연은 내 판에 영향 없음. 30초 유예 후 봇 대행, 대행 중엔 상대 바에 "연결 끊김 · 봇 대행" 표시.
- **초대 링크 안전**: 링크에는 방 코드만 담는다. 코드는 10분 만료·1회 입장이라 유출돼도 모르는 사람이 끼어들 창이 좁다. 방장이 입장자를 [내보내기]할 수 있다.
- **친구 목록 프라이버시**: 연락처 접근 없음. 친구 추가는 "같이 한 판 뒤" 또는 코드 교환으로만. 닉네임만 노출, 실명·전화번호 저장 안 함.
- **범위**: E(랭크 실시간)는 지표 없이는 착수하지 않는다. 친구 대전 + 고스트전만으로도 "온라인 대전" 탭은 성립한다.

## 8. 대전 모드(20웨이브) 밸런스 확정

생성(확정): `npm run waves -- --total 20 --hpGrowth 1.32 --countPer 0.8 --clearGoldBase 40 --clearGoldPerWave 8 --out src/data/duel-waves.json` (보스 5/10/15/20, 공중 4웨이브부터, 클리어 골드 40+8w). 측정: `npm run sim -- --mode duel`, `npm run shards -- --mode duel [--bossShards n --gradeS s --gradeA a]`. 회귀: `tests/Balance.test.ts` 대전 블록.

**전투 곡선 (확정)** — 봇 200판, 저지선 중앙값

| hpGrowth / 마릿수 | 하이카드 | 무전략 | 최선 | 최선 승리 | 판단 |
|---|---:|---:|---:|---:|---|
| 1.369 / 4+1.0w (첫 안: 40웨이브 최종값을 2:1 압축) | 7 | 9 | 14 | 0% | 라운드 수가 절반이라 성장이 못 따라감 → 너무 어려움 |
| 1.28 / 4+1.0w | 9 | 13 | 승리 | 56% | 너무 쉬움 |
| 1.31 / 4+1.0w | 8 | 12 | 17 | 7% | 근접 |
| **1.32 / 4+0.8w (채택)** | **8** | **13** | **18** | **10%** | 캠페인(23/25/32 of 40)의 절반 비율에 가장 가깝고, 승리가 드물되 가능 |

- 20웨이브는 40웨이브 곡선을 단순 압축하면 안 된다: 골드·유닛이 라운드마다 쌓이므로 성장 시간이 절반이면 적 성장도 그보다 완만해야 한다(1.369 → 1.32). 클리어 골드를 40+8w로 올려 업그레이드 속도를 보전했다.
- 하이카드 봇이 8인 것은 캠페인 비율(11.5)보다 낮지만, 대전은 상대와의 레이스라 절대 난이도보다 "둘 다 같은 벽"이 중요하다. 초반 4웨이브까지는 해골만 나와 하트를 잃을 일이 거의 없다.
